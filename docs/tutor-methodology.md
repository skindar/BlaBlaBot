# Методология разговорного тютора A1–A2 на маленьких моделях (Gemma-3-1B)

Продукт: GitHub Pages, всё в браузере, анонимно и офлайн. ASR — whisper,
TTS — Phonon, собеседник — WebLLM с Gemma-3-1B-IT (максимум Gemma-4 E2B).
Ограничение сверху — не модель, а вкладка: WebGPU, 4096 токенов контекста,
~28–35 tok/s у 1B. Методология должна давать **требуемое качество диалога
при Gemma-3-1B**; более крупные модели только улучшают его.

## 1. Диагноз: что именно не умеет 1B-модель

Измерено в этом же репозитории (docs/bench-results-2026-11-03.md, вкладка Bench):

| Симптом | Число |
|---|---|
| Строгий JSON tutor-ответа (полная схема) | gemma3-1b: **13%** |
| Строгий JSON (2-ключевая tiny-схема) | gemma3-1b: **25%** |
| Одноключевой JSON перевода | gemma3-1b: 7/8 |
| Дрейф в английский посреди урока | стабильно у всех tiny-моделей |
| Скорость/TTFT | ~33 tok/s, ~0.4–1 s TTFT — **достаточно** |

Вывод: маленькая модель плохо **планирует** (жирный JSON, свободная импровизация,
самоконтроль длины и языка), но прилично делает **простые акты**: короткое
натральное предложение по поводу конкретной фразы, классификацию, перевод
одной строки. Значит, архитектура хода должна состоять из простых актов, а
планирование — забрать в код.

**Главный принцип: код планирует, модель играет.** Детерминированный каркас
(сценарий, вопросы, ходы, чипы, валидаторы, шаблоны) задаёт качество пола;
модель добавляет живость: реакцию на слова ученика и микро-ответы на вопросы.

## 2. Педагогика A1–A2, зашитая в каркас

1. **Один ход = одна функция.** Ход тютора = [реакция] + [вопрос]. Ровно один
   вопрос, всегда в конце — ученик всегда знает, что от него ждут. Проверяется
   валидатором, а не просьбой в промпте.
2. **Понятный ввод (i+1).** Реплика тютора — короткие главные предложения,
   Present/Perfekt, лексика сценария + общеупотребительная A1–A2. Новый «полезный»
   слово вводится репликой-реакцией, не лекцией.
3. **Вопросная лестница.** Каждый шаг сценария держит: канонический вопрос,
   облегченный вариант-выбор (scaffold) и возвратную фразу. Короткий/пустой
   ответ ученика → не продвижение, а спуск по лестнице: «Magst du Kaffee
   oder Tee?». Вопрос ученика («Und du?») → короткий ответ от лица тютора и
   возврат того же вопроса.
4. **Коррекция для начинающих.** Максимум 1–2 на ход; правится только то, что
   мешает взаимопониманию и高频-паттерны: артикль/падеж, спряжение, порядок
   слов. Не правим выбор слов и содержание. Формат: карта исправления в UI
   (short explanation на языке интерфейса) + мягкий recast в реплике-реакции —
   модель получает исправление на вход и естественно употребляет верную форму.
5. **Чипы-подсказки = эталонные ответы** текущего вопроса. Они приходят из
   сценария мгновенно и без модели — идеальный уровень языка по построению.
6. **Лексика ученика** (v2): в реакцию подмешиваются слова из его словаря
   (localStorage) — повторение выученного в живом контексте.

## 3. Архитектура хода (tiny-tier, Gemma-3-1B)

```
ASR → user_text
 1. corrections-вызов      (single-key JSON, только последняя реплика)
 2. Детерминированный выбор хода (в коде, без модели):
      - ученик спросил?  → TUTOR_ANSWERS
      - ответ короткий?  → SCAFFOLD (не продвигаемся)
      - иначе            → REACT_AND_ADVANCE (следующий вопрос сценария)
 3. Микро-генерация (bare line, НЕ JSON):
      - reaction: 1 короткое предложение-реакция на слова ученика
        (+ подсказка recast, если есть исправление)
      - answer: 1–2 коротких предложения от лица тютора (если спросили)
    Валидаторы → при провале шаблон из сценария.
 4. Сборка реплики: [reaction|answer] + [вопрос из сценария]  — в коде.
 5. Полировка реплики (детерминированные валидаторы):
      язык цели (нет английского/кириллицы), ровно 1 «?», длина ≤ (A1:22/A2:32)
      слов, TTS-чистка (без *, эмодзи, разметки), без повтора прошлого вопроса.
 6. Чипы из сценария (0 мс, идеальный уровень).
 7. Перевод: два одиночных bare-line вызова (проверено: 7/8 у gemma3-1b),
    с существующими sanity-проверками (вопросы/числа/скрипт).
```

Пол-качество гарантируется конструкцией: худший случай = куртированный шаблон
реакции + куртированный вопрос — правильный язык, правильный уровень, никогда
не ломает диалог. Модель может только **улучшить** реакцию, не испортить ход.

Full-tier (Gemma-4 E2B, Qwen2.5-1.5B) идёт по прежнему JSON-контракту, но с
заземлением на сценарий: тема, словарь и предписанный вопрос в системном
промпте + те же валидаторы полировки.

## 4. Сценарии как данные

Сценарий = JSON в `src/lib/scenarios.ts`: тема, уровень, словарь, список ходов.
Каждый ход: `question`, `scaffold` (вариант-выбор), `reactions` (шаблоны
по тональности), `chips` (3 эталонных ответа), `tutorFacts` (факты о персоне
для вопросов «а ты?»). Продвижение: 1 осмысленный ответ = следующий вопрос;
конец сценария → переход на следующий по кругу с шаблонной фразой-переходом.

Тема из сайдбара подбирает сценарий по ключевым словам (frühstück → «Frühstück»),
свободные инструкции (`extraPrompt`) передаются в микро-генерацию как доп.
контекст. Для всех 5 языков есть минимум по одному generic-сценарию, чтобы
нигде не было пустого каркаса.

## 5. Рубрика качества («необходимый уровень»)

Детерминированные метрики (считаются автоматически на каждом прогоне):

| # | Метрика | Бар |
|---|---|---|
| 1 | Реплика на языке урока (нет англ./кир. дрейфа) | ≥ 99% |
| 2 | Ровно один вопрос в реплике | ≥ 95% |
| 3 | Длина ≤ 34 слова (A1 ≤ 22) | ≥ 95% |
| 4 | TTS-чистая реплика (без разметки/эмодзи) | 100% |
| 5 | Диалог не прерывается (нет поломанных ходов) | 100% |
| 6 | Вопрос не повторяет прошлый вопрос дословно | ≥ 95% |
| 7 | Чипы-подсказки есть | ≥ 95% ходов |
| 8 | Коррекции: только реальные ошибки (точность) | ≥ 80% |

Семантические (судьи-сабагенты на каждом прогоне, шкала 1–5):

| # | Критерий | Бар |
|---|---|---|
| 9 | Уместность реакции содержанию ответа | ≥ 4.0 |
| 10 | Соответствие лексики/грамматики уровню A1–A2 | ≥ 4.0 |
| 11 | Педагогика хода (i+1, scaffolding, тон) | ≥ 4.0 |
| 12 | Перевод передаёт смысл (не отвечает вместо перевода) | ≥ 4.5 |

## 6. Протокол тестирования (итерации с сабагентами)

1. **Harness**: `scripts/tutor-e2e.ts` (+ `tutor-e2e.html`, ранер
   `scripts/run-tutor-e2e.mjs`) гоняет настоящий `processChat` в реальном
   браузере (WebGPU, персистентный профиль кэширует модели) на трёх
   скриптованных учениках A1/A2 с типовыми ошибками: артикли, порядок слов,
   телеграфные ответы, вопросы тютору, выдуманные слова.
2. **Метрики** считаются детерминированно (см. п.5) в ранере.
3. **Судьи-сабагенты** (параллельно, независимые роли):
   - *методист* — семантическая оценка по рубрике 9–12 + список конкретных
     педагогических провалов с цитатами;
   - *инженер маленьких моделей* — анатомия провалов по сырым выводам,
     конкретные правки промптов/валидаторов/сценария.
4. Правки применяются к промптам/валидаторам/данным сценария — не к коду
   ради кода. Прогон повторяется, метрики сравниваются (baseline → v1 → v2).
5. Критерий выхода: детерминированные метрики в баре, семантические ≥ 4.0/4.5,
   либо задокументированное обоснованное отступление.

## 7. Результаты итераций

Прогоны: `scripts/run-tutor-e2e.mjs` (настоящий `processChat` в Chromium/WebGPU,
Gemma-3-1B-IT q4f16, персистентный профиль кэширует модель; 24 хода: 3
скриптованных ученика A1/A2 с типовыми ошибками). Транскрипты и метрики:
`docs/e2e/*.json`. Судьи — независимые сабагенты (методист DaF; инженер
малых моделей), каждая итерация судится по рубрике п.5.

### Журнал итераций

- **baseline** — старый tiny-tier (2-key JSON): числа терпимые, но содержание
  разваливается — вопросы-нонсеквиты уровня B1 («Was ist das Aufregendste…»),
  чипы отвечают на другой вопрос, галлюцинации коррекций («Ich heiße Sascha.» →
  «Sascha heiße ich.»), переводы-обрывки.
- **v1** — сценарный каркас: selectScenario + ходы (advance/scaffold/answer/
  farewell), микро-реакция bare-line, чипы из данных. Один вопрос 100%,
  латентность −35%, вопросы по сценарию. Осталось: мусорные реакции
  («wie du…»-скелеты), галлюцинации коррекций, метачат в переводах.
- **v2/v2.1** — по вердикту судей: few-shot реакции + blacklist мусорных
  паттернов + overlap-валидатор; фикс коррекций (few-shot с пустым списком +
  фильтры инверсии/дописывания/подмены слов); глоссарные переводы вопросов/
  прощания; гейт релевантности (нерелевантный ответ → переспрос, cap 2);
  банк персоны; stop-последовательности (латентность реакций ×6 вниз);
  чистка чужих скобок/скриптов в переводах; запрет коррекций обрывков <3 слов.
- **v3** — три must-fix финального вердикта: (1) отбраковка коррекций, чей
  «исправленный» фрагмент сам нарушает V2 — тютор больше никогда не озвучивает
  сломанный немецкий; (2) скрипт-валидация переводов (иероглифы/латиница в
  русской строке → переспрос → глоссарный пол); (3) детерминированная
  подстановка фактов персоны в ответах на личные вопросы (score≥1) —
  «Ich heiße Max»/«Ich trinke Wasser» исчезли из TUTOR_ANSWERS-ходов.

### Вердикт судьи по v3

Детерминированные метрики — все в баре; R2 взят (4.3); R1/R3/R4 не взяты.
Состав провалов принципиально изменился: в baseline ломался сам каркас, в v3
кардан держит всё — остаточные потери сконцентрированы в двух модельных
микро-слоях (реакция и перевод реакции).

### Роадмап v4 (по вердикту судьи, по убыванию эффекта)

1. **Анти-факт-лейк в реакциях** (убийца R1): модель в REACT-реакциях
   приписывает себе факты/имена ученика («Ich heiße Max», «Ich komme aus dem
   Land», «Hallo, ich bin Maria»). Фикс: убрать персону из контекста
   reaction-промпта + валидатор «реакция не начинается с Ich heiße/wohne/komme/
   trinke» вне TUTOR_ANSWERS; валидатор отсылки к теме ответа (p2 четыре хода
   про футбол — ни одной реакции про футбол).
2. **Анти-луп сценария + recall коррекций** (убийцы R3): дословные повторы
   переспросов («Woher kommst du?» ×3) — advance по пересечению с chips;
   recall 3/8 (V2/падежи не ловятся) — targeted few-shot по пропущенным
   паттернам (mit+Dativ, V2 с «gestern/nächste Woche»).
3. **Санитайзер переводов** (R4): запрет пустого перевода осмысленной строки,
   проверка «тип вопроса сохранён» (бэк-трансляция), запрет ответа-вместо-
   перевода («Wie geht es dir?» → «А у вас?»).

### Ограничения протокола

- n=24 ходов, 1 прогон на итерацию: семантические оценки ±0.2–0.3 (судья
  отмечает, что Δ R2/R3 между v2.1 и v3 — в пределах шума).
- Скрипт-валидация переводов (fix #2) не имела триггеров в чистом прогоне —
  нужна негативная персона в harness (дрейф, латиница в русском).
- Судейство одним методом-объединением (LLM-судья); для релиза — двойное
  слепое судейство и фиксация персонального состава судей.

## 8. Режим дневника (поддерживающий слушатель)

Переключатель в сайдбаре меняет роль тютора: из сценарного собеседника —
в **поддерживающего слушателя**. Пользователь рассказывает, как прошёл день,
тютор только поддерживает: короткая реакция + слушающий вопрос из банка
(«Und was war dann?», «Wie hast du dich gefühlt?», «Wirklich? Erzähl mehr!»),
без новых тем, без самопрезентаций («I» запрещён промптом и валидатором),
без коррекций в речи (карточка коррекции и «исправленная» версия — только в
UI и в записи дневника).

Каждая реплика ученика становится записью дневника: дословный текст,
перевод на язык интерфейса и, при наличии коррекций, исправленная версия.
Записи группируются по датам, синхронизируются на Google Drive (вместе с
чатом и карточками). Проверено прогоном `E2E_DIARY=1` на Gemma-3-1B
(docs/e2e/diary-mode-v2-gemma3.json): 7 ходов рассказа о дне — 0 ошибок,
вопросы только из банка слушателя, реакции короткие и тёплые, все записи
на месте, 374 мс на ход.
